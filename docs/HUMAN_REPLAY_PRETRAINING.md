# Human replay pretraining

Tetra can bootstrap its policy/value network from consented TETR.IO multiplayer replay files before continuing with the normal self-play and Reanalyze loop.

The implementation follows the useful high-level shape of MochBot/fusion's public training pipeline: human replay corpus -> preprocessing -> policy/value data -> training. No MochBot source code is vendored here. The adapter was implemented independently against the public replay data contract and Tetra's existing engine interfaces.

## Data flow

```text
consented .ttrm files
  -> trainer/ttrm_ingest.py
  -> content-addressed normalized replay cache
  -> tetra_cli import-human-replay
  -> C++ legal-action validation + tokenization
  -> human_*.tetradat + manifest.json
  -> trainer/human_pretrain.py
  -> human_pretrain.pt
  -> trainer/auto_improve.py
  -> self-play -> Reanalyze -> train -> Arena gate
```

Python only normalizes the JSON surface. C++ remains authoritative for boards, rotations, legal placement generation, hold semantics, tokenization, action embeddings, and dataset serialization. This prevents a second game implementation from defining model-facing state or action semantics.

## Build

Use the normal engine build:

```sh
make tools
```

If `build/` already contains objects from another platform, use an isolated directory instead of deleting existing artifacts:

```sh
make BUILD=build-human tools
```

Then pass that executable with `--engine`.

## Bulk import

```sh
python trainer/import_human_replays.py /path/to/consented/replays \
  --engine build/tetra_cli \
  --output-dir data/human_replay_shards \
  --cache-dir data/human_replay_cache \
  --samples-per-shard 4096 \
  --workers 16 \
  --ruleset league \
  --strict-source
```

Inputs may be files or directories; directory discovery is recursive. The importer produces validated `.tetradat` shards, a content-addressed cache, and `manifest.json` with per-source and per-shard counts and hashes.

A demonstrated placement is accepted only when it matches a legal macro action generated by Tetra's C++ move generator. Invalid state, replay-execution failure, and no-legal-match cases are counted separately rather than guessed into the dataset.

## One-command bootstrap training

```sh
python trainer/human_pretrain.py /path/to/consented/replays \
  --engine build/tetra_cli \
  --device cuda \
  --require-gpu \
  --steps 5000 \
  --batch 256 \
  --save models/human_pretrain.pt
```

The default human-data loss mix is policy `1.0`, value `0.25`, and zero weight for local auxiliary and timing objectives. Human keyboard timing is not the same target as Tetra's strategic delay action, so human data teaches placement/hold policy and final game result while timing and local auxiliary targets remain the responsibility of self-play/Reanalyze.

Use `--resume` to start from an existing checkpoint. Use `--skip-import` to train from existing human shards without rebuilding them.

## Continue self-improvement

```sh
python trainer/auto_improve.py \
  --champion models/human_pretrain.pt \
  --bootstrap-replay-dir data/human_replay_shards \
  --reanalyze \
  --device cuda
```

`--bootstrap-replay-dir` adds every `.tetradat` file below that directory to the fixed replay set, deduplicates paths also named through `--bootstrap-replay`, and keeps them outside the rolling fresh-self-play window.

## Replay reconstruction contract

The normalizer accepts both canonical top-level replay-set data and older collector-style `replay.rounds` data. As in MochBot/fusion's public preprocessor, a demonstrated turn is reconstructed from recorded `keydown` events and closed by `hardDrop`; Tetra then independently checks the resulting placement against its legal move set.

The importer intentionally does not yet reinterpret TETR.IO interaction events as Tetra incoming-line events. Their ownership/confirmation semantics must be established before mapping them into the simulator; guessing would silently corrupt state. A high no-legal-match rate in real versus data should therefore be treated as a reason to inspect the source and importer, not as a reason to weaken validation.

## Validation

```sh
python -m unittest trainer.test_ttrm_ingest
make test
```

`tests/data/human_replay_sample.ttrm` is a small canonical-format fixture. An end-to-end fixture import should yield one game, two hard-drop turns, two validated samples, and zero execution/unmatched skips.

Before a large X/X+ pretraining run, import a representative subset and inspect `manifest.json`. The acceptance ratio is a reconstruction/data-quality signal; keep validation strict.
